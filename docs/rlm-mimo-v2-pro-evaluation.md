## 1. Спецификации моделей

### Xiaomi MiMo-V2-Pro
- **Контекстное окно**: 1,048,576 токенов (1M)
- **Параметры**: >1T total (Mixture of Experts)
- **Оптимизация**: Агентские сценарии, tool-use
- **Цена (OpenRouter)**: $1.00/M input, $3.00/M output
- **Доступность**: Nous Research endpoint, OpenRouter
- **Позиционирование**: Флагманская модель Xiaomi для агентных задач

### OpenAI GPT-5 Nano
- **Контекстное окно**: 400,000 токенов
- **Параметры**: Не раскрываются (компактная модель)
- **Оптимизация**: Быстрые взаимодействия, ultra-low latency
- **Цена (OpenRouter)**: $0.05/M input, $0.40/M output
- **Доступность**: OpenRouter, OpenAI API
- **Позиционирование**: Самая маленькая и быстрая модель линейки GPT-5

### OpenAI GPT-5 Mini (baseline)
- **Контекстное окно**: 400,000 токенов
- **Цена (OpenRouter)**: $0.25/M input, $2.00/M output
- **Позиционирование**: Компактная модель для лёгких reasoning задач

## 2. Требования RLM (из анализа кода)

RLM предъявляет следующие требования к модели:

### 2.1 Генерация валидного Python-кода в ```repl блоках
Парсер (`parsing.py`) ищет блоки по regex: `` ```repl\s*\n(.*?)\n``` ``
- Модель ДОЛЖНА строго использовать тег `` ```repl `` (не `` ```python ``)
- Код должен быть валидным Python, выполняемым через `exec()`
- Модель должна понимать, что код будет выполнен, и ожидать результат

### 2.2 Рекурсивное мышление через rlm_query / llm_query
Системный промпт (~2500 токенов) объясняет:
- `llm_query(prompt)` — простые одношаговые запросы
- `rlm_query(prompt)` — рекурсивные вызовы с собственным REPL
- `llm_query_batched` / `rlm_query_batched` — параллельные вызовы
- Модель должна понимать РАЗНИЦУ между llm_query и rlm_query

### 2.3 Понимание FINAL / FINAL_VAR
Парсер проверяет:
- `FINAL(ответ)` — прямой финальный ответ
- `FINAL_VAR(имя_переменной)` — ссылка на переменную из REPL
- Модель должна корректно формировать эти вызовы

### 2.4 Итеративное взаимодействие
RLM работает циклически (до 30 итераций по умолчанию):
1. Модель генерирует ответ с ```repl блоками
2. REPL выполняет код, возвращает stdout/stderr
3. Результат добавляется в историю
4. Модель генерирует следующий шаг
5. Повтор до FINAL или бюджет исчерпан

### 2.5 Работа с большими контекстами
Системный промпт включает метаданные контекста:
- Тип контекста, общая длина в символах
- Размеры чанков
- Модель должна эффективно разбивать и обрабатывать большие контексты

## 3. Оценка MiMo-V2-Pro

### Сильные стороны ✅

1. **Контекст 1M токенов** — в 2.5x больше GPT-5 Nano (400K). Для RLM это критично, так как итеративная история растёт быстро (системный промпт + контекст + история REPL + результаты выполнения).

2. **Оптимизация для агентных сценарий** — Xiaomi явно позиционирует модель для agentic workflows, что напрямую соответствует архитектуре RLM (REPL + tool use + multi-step reasoning).

3. **1T+ параметров (MoE)** — крупная модель с потенциально высоким качеством reasoning и code generation.

4. **Доступность через Nous Research** — низкая латентность (~800-1600 tps), прямой endpoint без посредников.

5. **Совместимость с OpenAI API** — RLM использует стандартный OpenAI-совместимый клиент (`OpenAIClient`), работает с любым base_url.

### Слабые стороны / Риски ⚠️

1. **Неизвестное качество генерации ```repl блоков** — нет публичных бенчмарков по format compliance. Модель может генерировать `` ```python `` вместо `` ```repl ``.

2. **Цена в 20x дороже GPT-5 Nano** — $1.00/M+$3.00/M vs $0.05/M+$0.40/M. При 30 итерациях RLM стоимость накапливается быстро.

3. **Нет данных о следовании системному промпту** — RLM system prompt (~2500 токенов) содержит специфичные инструкции. Неизвестно, насколько точно MiMo-V2-Pro им следует.

4. **Модель новая** — меньше community testing для edge cases рекурсии.

### Количественная оценка стоимости (на примере задачи)

Типичная RLM-сессия:
- Системный промпт: ~2,500 токенов
- Контекст задачи: ~5,000 токенов
- 10 итераций × ~1,500 токенов ответа = 15,000 output токенов
- История растёт: ~50,000 input токенов суммарно

| Модель | Input Cost | Output Cost | Итого |
|--------|-----------|------------|-------|
| MiMo-V2-Pro | $0.050 | $0.045 | **$0.095** |
| GPT-5 Nano | $0.0025 | $0.006 | **$0.0085** |
| GPT-5 Mini | $0.0125 | $0.030 | **$0.0425** |

MiMo-V2-Pro дороже GPT-5 Nano в **11 раз**.

## 5. Рекомендация

### Главный вывод

**MiMo-V2-Pro ПОДХОДИТ для RLM, но НЕ ОПТИМАЛЕН как замена GPT-5 Nano по умолчанию.**

### Обоснование

1. **Техническая совместимость**: MiMo-V2-Pro совместим с RLM через стандартный OpenAI-совместимый клиент. Контекст 1M токенов — значительное преимущество для итеративных RLM-сессий с растущей историей.

2. **Стоимость — главный барьер**: 11x дороже GPT-5 Nano. RLM по своей природе делает много вызовов (итерации + рекурсивные sub-calls). Это делает MiMo-V2-Pro экономически нецелесообразным для большинства задач.

3. **Качество не проверено**: Нет данных о том, что MiMo-V2-Pro лучше GPT-5 Nano в генерации валидного ```repl-кода и следовании сложному системному промпту RLM.

### Рекомендуемая стратегия

**Использовать двухуровневую архитектуру:**

```
Уровень 0 (Root RLM): GPT-5 Nano или GPT-5 Mini
  └─ Уровень 1 (Sub-calls): GPT-5 Nano (llm_query)
  └─ Уровень 1 (Deep sub-calls): MiMo-V2-Pro (rlm_query для сложных задач)
```

Или через RLM `other_backends`:
```python
rlm = RLM(
    backend="openrouter",
    backend_kwargs={"model_name": "openai/gpt-5-nano"},  # основной
    other_backends=["openrouter"],
    other_backend_kwargs=[{"model_name": "xiaomi/mimo-v2-pro"}],  # для сложных sub-calls
)
```

### Когда использовать MiMo-V2-Pro для RLM

✅ **Подходит**:
- Задачи с контекстом >200K токенов (преимущество 1M окна)
- Сложные multi-step reasoning задачи, где важен размер модели
- Когда бюджет не критичен
- Эксперименты с новыми архитектурами

❌ **Не подходит**:
- Массовые вызовы (batch processing) — слишком дорого
- Простые задачи, где GPT-5 Nano достаточно
- Продакшен с контролем бюджета

### Альтернативы для рассмотрения

| Модель | Цена (in/out) | Контекст | Комментарий |

   - Format compliance (% валидных ```repl блоков)
   - Количество итераций до FINAL
   - Качество финального ответа
   - Общую стоимость

2. **Проверить MiMo-V2-Flash**: Более лёгкая версия может дать лучший баланс цена/качество.

## ДОПОЛНЕНИЕ: MiMo-V2-Flash — лучший кандидат

При дополнительном анализе обнаружена модель **Xiaomi MiMo-V2-Flash**, которая может быть лучшим выбором для RLM:

### MiMo-V2-Flash
- **Контекст**: 262,144 токенов
- **Архитектура**: MoE, 309B total / 15B active параметров
- **Цена (OpenRouter)**: $0.09/M input, $0.29/M output
- **Позиционирование**: Open-source, оптимизированная для скорости

### Сравнение всех трёх моделей Xiaomi

| Модель | Контекст | Input $/M | Output $/M | Итого/сессия* |
|--------|----------|-----------|------------|---------------|
| MiMo-V2-Pro | 1M | $1.00 | $3.00 | $0.095 |
| MiMo-V2-Omni | 262K | $0.40 | $2.00 | $0.052 |
| **MiMo-V2-Flash** | 262K | **$0.09** | **$0.29** | **$0.0089** |
| GPT-5 Nano | 400K | $0.05 | $0.40 | $0.0085 |

*Типичная RLM-сессия (50K input, 15K output)

### Ключевое открытие

**MiMo-V2-Flash стоит почти СТОЛЬКО ЖЕ, как GPT-5 Nano** ($0.0089 vs $0.0085 за сессию), но:
- Больше параметров (15B active vs компактная GPT-5 Nano)
- Заявленная оптимизация для агентных сценарий
- Open-source (можно запустить локально)
- Доступна через Nous Research endpoint

### Обновлённая рекомендация

**Для начальной интеграции RLM рекомендуется MiMo-V2-Flash**, а не MiMo-V2-Pro:

1. Экономически сопоставим с GPT-5 Nano
2. Потенциально лучшее качество (15B active params)
3. Можно A/B тестировать без значительных затрат
4. Если Flash покажет хорошие результаты → можно升级 до Pro для сложных задач

```python
# Рекомендуемая конфигурация
rlm = RLM(
    backend="openrouter",
    backend_kwargs={"model_name": "xiaomi/mimo-v2-flash"},  # основной
    max_iterations=30,
    max_depth=2,
)
```
